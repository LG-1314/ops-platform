# 企业级运维服务器 · 全维度管理平台 — 技术方案与实施规划

> 状态：方案 v1.0 ｜ 形态：跨平台桌面应用 ｜ 技术栈：Electron + React + TypeScript + Vite + Node + SQLite
> 一句话定位：把 7 大运维技能/专家编排进一个统一桌面平台，提供「资产纳管 → 全栈诊断 → 智能巡检 → 知识检索 → 自动化治理 → DevOps 编排 → 容器集群」的全维度能力，并内置「可查资料和相关项目」的关联知识视图。

---

## 1. 产品定位与目标用户

- **形态**：桌面应用（Windows / macOS / Linux 一体包），企业内网/单机均可部署。
- **目标用户**：运维工程师、SRE、运维负责人、一线值班。
- **核心价值**：
  1. 把分散的运维能力（诊断命令、知识库、巡检、自动化、K8s 编排）收敛到一个工作台。
  2. 所有诊断**只读、不修改系统**，结果结构化、可追溯、可导出。
  3. 内置「资料/相关项目」关联视图：任一资产可回溯其关联的项目、工单、知识文档，实现"问题→资料→处置"闭环。

## 2. 技术栈决策（为什么是"最好且可行"）

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面框架 | **Electron 28** | 跨平台、Node 主进程可原生执行系统命令、生态最成熟；本机无 Rust 工具链，Tauri 暂不可行 |
| 前端 | **React 18 + TypeScript + Vite** | 组件化、类型安全、HMR 快、企业团队易维护 |
| 主进程能力 | **Node.js（child_process）** | 直接执行标准系统命令并解析，零额外依赖 |
| 状态管理 | **Zustand** | 轻量、无样板代码 |
| 图表 | **ECharts** | 运维仪表盘（CPU/内存/磁盘趋势）首选 |
| 本地存储 | **SQLite（better-sqlite3）** | 指标、报告、知识缓存落地，离线可用 |
| 调度 | **node-cron** | 定时巡检 |
| 文档/报告 | **Markdown → PDF** | 巡检报告导出 |

> 注：若后续环境具备 Rust 工具链，可将诊断引擎迁移至 Tauri 以减小包体积、提升安全；接口层保持不变（capability provider 抽象）。

## 4. 系统架构

```
┌────────────────────────── 渲染进程 (React) ──────────────────────────┐
│  仪表盘 │ 系统体检 │ 知识检索 │ 巡检报告 │ 自动化 │ 集群 │ 设置        │
└───────────────▲───────────────────────────────▲──────────────────────┘
                │ IPC (contextBridge)            │
┌───────────────┴──────────── 主进程 (Node) ────┴──────────────────────┐
│  Capability Bus（能力总线）                                           │
│   ├─ DiagnosticsProvider  ├─ KnowledgeProvider  ├─巡检Scheduler       │
│   ├─ AlertEngine          ├─ Storage(SQLite)   ├─ AutomationProvider  │
│   └─ ClusterProvider                                                │
│  执行层：child_process 调标准系统命令（跨平台适配）/ 调用技能 API        │
└──────────────────────────────────────────────────────────────────────┘
```

- **Capability Provider 抽象**：每个技能封装为一个 provider，统一 `run(input) → {status, data, suggestions}` 接口，UI 与调度层只依赖总线，不关心底层实现。
- **只读原则**：诊断类 provider 仅执行只读命令，绝不修改系统配置。

## 6. 「可查资料和相关项目」模块设计

- **资料检索**：本地全文索引（知识库 FAQ + 导入的运维文档），支持关键词/现象描述检索，返回匹配答案与出处链接。
- **关联视图**：以资产（主机/IP/服务）为中心，聚合其关联的项目、历史工单、相关知识点、近期巡检报告，形成可点击的关联图谱。
- **数据来源**：内置运维监控FAQ知识库检索能力；支持导入 Markdown/PDF 运维文档建立本地索引；关联数据存 SQLite。

## 7. 跨平台命令适配（诊断引擎核心）

| 指标 | Windows (PowerShell) | macOS | Linux |
|------|----------------------|-------|-------|
| CPU 使用率 | `Get-Counter '\Processor(_Total)\% Processor Time'` | `top -l1` / `ps` | `top -bn1` / `mpstat` |
| 内存 | `Get-CimInstance Win32_OperatingSystem` | `vm_stat` / `sysctl` | `free -m` |
| 磁盘 | `Get-PSDrive` / `wmic` | `df -h` | `df -h` |
| 负载/运行时间 | `systeminfo` / `net stats` | `uptime` | `uptime` |
| 核心数 | `Get-CimInstance Win32_Processor` | `sysctl -n hw.ncpu` | `nproc` |

> 引擎按 `process.platform` 自动选择命令，统一解析为 `{value, unit, status}` 结构。

## 9. 风险与边界

- 技能提供的是**能力/知识**，不是现成可运行系统，需封装进 provider。
- 部分诊断需**管理员/root** 权限，应用需提示并以提权方式执行敏感命令。
- 所有诊断**只读**，重大异常建议转人工/运维团队，应用不自动改动系统。
- 当前沙箱无显示环境，GUI 实际运行需用户在本地 `npm run dev` 验证。
